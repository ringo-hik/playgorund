### 통합 요구사항 전문 — 한 항목도 빠짐없이 문장형으로 정리

1. **TreeView 구조**는 VS Code 기본 UI만 활용하며, 각 프로젝트를 최상위 노드로 두고 그 하위에 `Layer Build(기존 Dev Build → 명칭 변경)`, `Rel Build`, `Commit Build` 세 노드를 배치한다.
2. 각 빌드 노드의 하위에는 고정적으로 **`Build Configuration`**, **`Configuration Setting`**, **`Build History`** 세 하위 트리를 두며, 별도의 **`Build In Progress`** 노드에서 현재 진행 중인 빌드를 모아 보여 준다.
3. **`Build Configuration`** 트리 안에는 `Build`, `SAM`, `Coverity`, `DoBEE`, `OnBoard Test` 다섯 항목만 표시하고, 항목이 **Enable** 상태일 때만 체크박스가 활성화된 형태로 나타내며, 각 항목의 상태를 완료·대기·진행중 중 하나로 표시한다(상태 값은 SWDP API가 제공).
4. **테스트(위 다섯 항목) 표시 방식**은 TreeView 하위 뷰를 사용한 체크박스 리스트로 구성해 가독성을 높인다.
5. **Dev Build**라는 용어는 문서·UI 전체에서 \*\*`Layer Build`\*\*로 통일해 사용한다.
6. **프로젝트 이름**은 예시처럼 **`ABC_TEST_PROJECT`** 형식으로 표기한다.
7. 프로젝트 관련 정보(REPO, Branch, Commit, Build Option 등)는 트리에서 모두 펼치지 않고, 상위에 **`Project Setting Info`** 노드 하나만 보여 준 뒤 클릭 시 상세 정보를 별도 패널로 출력하며, 해당 패널에서 JSON 기반 편집·저장 기능을 제공한다.
8. **Project Settings** 버튼(또는 트리 노드)을 누르면 **Build Agent Help** 스타일의 설정 화면을 띄워 사용자가 구성 값을 수정·저장할 수 있게 한다.
9. **설정 파일 구조**는

   * `.swdp/{project_name}/rel-build.config`
   * `.swdp/{project_name}/layer-build.config`
   * `.swdp/{project_name}/commit-build.config`
     로 분리‧저장하며, 프로젝트가 선택되면 SWDP API로부터 받은 최신 빌드 정보를 해당 JSON 파일에 덮어쓴다(파일이 이미 존재하면 기존 내용을 유지).
10. 각 빌드 노드 오른쪽에는 **재생(▶) 버튼**을 두어 **Start Build**를 실행하며, 버튼 클릭 시 확인 알림을 거쳐 빌드를 시작한다.
11. **빌드가 실제 수행된 화면 예시**에서는 이 재생 버튼을 눌러 빌드가 “진행 중”으로 표시된 뒤, 완료 시 TreeItem 배지 색상과 상태 텍스트가 변경되는 모습을 보여 준다(이모지는 사용하지 않는다).
12. **빌드 결과 History**는 `Build History` 트리에서만 보여 주며, `Build #121 Success (완료 시간)` 형식으로 표시하고, 빌드부터 OnBoard Test까지 모든 단계가 완료된 항목만 노출한다. 역사 데이터는 SWDP API로 가져온다.
13. **빌드 설정 항목**(JSON 필드)은 20개가 넘으므로, 편집 화면에서는 토글(on/off)과 텍스트 입력 두 종류 입력 컴포넌트를 사용해 전체 항목을 수정 가능하게 한다.
14. **PUMBA Remote Build 뷰**는 SWDP Build와 유사한 TreeView 구조를 갖되, **프로젝트 선택·Rel/Layer 트리 없이** 바로 `Start Build`, `Configuration Setting`, `Build History` 세 노드만 제공한다.
15. **Build Agent Help** 화면 레이아웃과 정보 표현 방식은 현재 디자인을 유지하며, 이모지를 제거해 최대한 심플하게 한다.
16. **Bamboo 로그 실시간 스트리밍 API가 없으므로** 빌드 진행 상태는 “진행 중”으로만 표기하고, 사용자가 TreeView 새로고침 또는 VS Code 탐색 시점에 SWDP API를 호출해 상태를 갱신한다.
17. **프로젝트 변경 버튼**은 “SWDP BUILD” View에서 프로젝트를 선택한 뒤에도 보이도록 하여, 사용자가 언제든 프로젝트를 교체할 수 있게 한다.
18. 모든 기능 요구사항과 작업 항목은 **`todo.md`** 파일에 기록하며, 누락 없이 다음과 같이 작성한다.

```
# todo.md

1. SWDP BUILD
   1.1 프로젝트 선택 후 “프로젝트 변경” 버튼 구현  
   1.2 프로젝트 하위에 Rel, Layer, Commit Build 트리 생성  
   1.3 각 빌드 트리별 설정 파일 경로 분리(.swdp/{project}/...)  
   1.4 SWDP API로 빌드 정보 수신 → JSON 덮어쓰기 로직  
   1.5 Build Configuration 하위에 Build/SAM/Coverity/DoBEE/OnBoard Test 항목 체크박스 표시  
   1.6 Configuration Setting 패널에서 JSON 편집·저장 UI 구현  
   1.7 Build History 트리에서 완료된 빌드만 목록화(번호·결과·시간)  
   1.8 빌드 시작(▶) 버튼 및 확인 알람 연결  
   1.9 Build In Progress 노드에서 진행 중 빌드 실시간 표기

2. PUMBA REMOTE BUILD
   2.1 Start Build / Configuration Setting / Build History 3개 트리만 표시  
   2.2 설정 파일 로딩·편집·저장 기능 구현  
   2.3 History 트리에 완료 빌드 목록 표시(번호·결과·시간)

3. 공통
   3.1 TreeView 새로고침 시 SWDP·PUMBA API Polling으로 상태 갱신  
   3.2 Dev Build 명칭을 Layer Build로 전면 교체  
   3.3 Build Agent Help 화면·Info 패널 디자인 최적화(이모지 제거)  
   3.4 프로젝트 이름 규칙 ‘ABC_TEST_PROJECT’ 적용 예시 반영
```

이 문서는 사용자가 제시한 모든 요구사항을 빠짐없이 문장 형태로 정리한 전문이다.
