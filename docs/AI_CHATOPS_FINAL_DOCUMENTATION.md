# AI ChatOps Framework 고도화

## SWDP 기반 주간보고 자동생성 에이전트 설계문서

**문서 버전**: v1.0  
**작성일**: 2025.07.19  
**분류**: 기술 아키텍처 및 사업 전략 문서

---

## 1. 개요

### 1.1 프로젝트 목적

SWDP 자원과 권한을 활용한 지능형 주간보고 자동생성 에이전트 구축으로 개발자 생산성 극대화 및 보고 업무 자동화를 달성한다.

### 1.2 핵심 혁신

**Context Engineering**: LLM의 컨텍스트 윈도우에 적절한 정보를 최적 시점에 제공하는 기법으로, 대용량 JIRA 데이터의 효율적 처리와 Multi-LLM 전략을 통한 성능 최적화를 구현한다.

---

## 2. 기획 의도

### 2.1 문제 인식

- 개발자의 주간보고 작성 부담 과중
- JIRA 기반 업무 관리 문화 정착 필요
- 수작업 보고서 작성의 비효율성

### 2.2 해결 방안

**AI업계 원칙 준수**: "6개월 뒤 사라질 서비스를 만들지 말라"는 철학에 따라 GPT-5 도입 후에도 지속 가능한 도메인 특화 서비스 구현

**원클릭 완성**: 사용자 정보 자동 인식 → JIRA 데이터 수집 → 보고서 생성의 완전 자동화

### 2.3 기대 효과

- 주간보고 작성 시간: 2시간 → 5분 이내
- JIRA 기반 업무 관리 조직 채택률: 60% → 95%
- 개발자 만족도: 3.2/5.0 → 4.5/5.0

## 3. 기술 스택

### 3.1 Backend 기술

```
언어: Java 8
프레임워크: Spring Framework 2.x (기존 레거시 시스템 호환)
데이터베이스: SWDP DB 연동
API 통합: JIRA REST API, Bitbucket API (제한적 사용)
```

### 3.2 Frontend 기술

```
언어: JavaScript, Vue.js 3
개발 방식: 하이브리드 (사외 바이브코딩 + 사내 통합)
UI 프레임워크: Custom Markdown Framework
테마: 다양한 도메인 특화 테마 제공
```

### 3.3 AI 모델 구성

**Multi-Model Parallel Processing**:

- **Narrans (ML P/J)**: 기본 언어 처리 및 추론
- **Gauss Thinking Model**: 복잡한 의사결정 처리
- **Llama Maverick**: 대용량 컨텍스트 처리
- **Gemma3**: 단순 텍스트 처리

## 4. 기술 아키텍처

### 4.1 시스템 구조

```
┌─────────────────────────────────────────┐
│            AI ChatOps Framework         │
├─────────────────────────────────────────┤
│ Intent Parser │ Query Engine │ Generator │
├─────────────────────────────────────────┤
│         Data Integration Layer          │
├─────────────────────────────────────────┤
│   JIRA API   │ Bitbucket API │ SWDP DB  │
└─────────────────────────────────────────┘
```

### 4.2 데이터 처리 전략

**선택적 데이터 소스**:

- ✅ JIRA 이슈 데이터 (핵심)
- ❌ Bitbucket 코드 diff (효용성 낮음)
- ❌ Confluence Wiki (API 제한 + 데이터 품질 저하)

### 4.3 Context Engineering 최적화

**문제**: JIRA JQL 결과 대용량 데이터로 인한 LLM 컨텍스트 한계
**해결**:

- 불필요 정보 제거 및 핵심 데이터 추출
- Multi-LLM 병렬 처리로 컨텍스트 압축
- 도메인별 프롬프트 최적화

## 5. 개발 방법론

### 5.1 하이브리드 개발 전략

**Backend**: 사내 기존 방식 (보안 및 안정성)
**Frontend**: 사외 바이브코딩 (Claude Code 활용)

### 5.2 바이브코딩의 성과

- "전혀 손댈 수 없는 영역"의 기능 개발 가능
- 기존 개발 경험 범위의 질적 확장
- 환경 구축 복잡성 대비 혁신적 기술 습득

### 5.3 Prompt Engineering

**Knowledge Distillation**: 상용 LLM(Claude/GPT) → 내부 LLM 지식 전이
**Few-shot Learning**: JIRA 9.12 서버용 JQL 최적화 예제 제공
**Anti-pattern**: 일관된 답변 품질을 위한 오류 패턴 방지

## 8. 기획 방향

### 8.1 Prompt-as-Code 패러다임

- 코드 배포 → 프롬프트 문서 배포
- 비개발자도 AI 서비스 구축 가능
- 실시간 피드백 반영 (재배포 없음)

### 8.2 AI-Driven DevOps 구현

- 단순 챗봇 → 종합 DevOps 프레임워크
- 모든 비즈니스 로직의 AI 위임
- Context-aware 서비스 오케스트레이션

### 8.3 향후 발전 방향

**단계 1**: 주간보고 자동화
**단계 2**: 조직별/프로젝트별 정기 보고서 확장
**단계 3**: 모든 보고 업무의 AI 자동화
**최종 목표**: 보고서 작성 업무 완전 배제

---

## 9. 구현 계획

### 9.1 핵심 기능

1. **사용자 인식**: SWDP → 사용자 정보 → JIRA Key 자동 매핑
2. **데이터 수집**: JQL 쿼리 최적화를 통한 효율적 데이터 추출
3. **보고서 생성**: Multi-LLM 협업을 통한 고품질 보고서 작성

### 9.2 작동 원리

```
사용자 요청 → Intent 분석 → 최적 LLM 선택
→ JIRA 데이터 수집 → Context Engineering
→ 보고서 생성 → 사용자 제공
```

### 9.3 품질 보장

- JIRA 9.12 서버 최적화 JQL
- 팀 주간보고 템플릿 표준화
- 일관된 포맷 및 품질 보장

---

## 10. 결론

본 AI ChatOps Framework는 Context Engineering과 Multi-LLM 전략을 통해 기존 한계를 극복하고, 하이브리드 개발 방법론을 통해 혁신적 사용자 경험을 제공한다.

단순한 자동화 도구를 넘어 조직의 업무 패러다임을 변화시키는 전략적 플랫폼으로서, 모든 지식 근로자가 창조적 업무에 집중할 수 있는 AI 기반 조직 문화 구현을 목표로 한다.
